# Span

**Учёт времени, который заканчивается счётом**

Неделя — это сетка, а не лента. Таймер запускается одним нажатием, видно, куда ушла неделя, а месяц превращается в позиции для счёта.

## Зачем

Между блокнотом с часами и корпоративной системой учёта нет ничего для одного человека: облачные трекеры требуют подписки и аккаунта на каждого, корпоративные — внедрения.

Span делает ровно одну вещь целиком: от нажатия «старт» до готовых строк, которые можно вставить в счёт. Он знает про ставку, округление и то, что часть работы не оплачивается.

## Что умеет

- **Сетка недели** — проекты сверху вниз, дни слева направо, итоги по обоим краям. Пустой четверг виден так же ясно, как занятый вторник
- **Один идущий таймер** — запуск нового останавливает предыдущий: параллельные таймеры порождают часы, которых не было
- **Округление у клиента** — по минутам или вверх до 5 / 10 / 15 / 30 минут, как договорились
- **Ставка у клиента, переопределение у проекта** — правки по старому договору могут стоить дешевле новой работы
- **Оплачиваемое и нет** — внутренние созвоны и переделка своей ошибки остаются в отчёте и не попадают в счёт
- **Позиции счёта** — одна строка на проект: описание, часы, ставка, сумма. Копируются прямо в [GoBill](https://github.com/dripips/gobill)
- **Выгрузка CSV** — тот же период, по строке на запись
- **Три языка** — русский, английский, немецкий
- **Светлая и тёмная темы** — идущий таймер помечен формой и подписью, а не только цветом
- **Один бинарник** — Go и SQLite, никаких внешних сервисов
- **Демо-данные** — одна команда наполняет две недели правдоподобного фриланса

## Быстрый старт

```bash
git clone https://github.com/dripips/span.git
cd span
go build -o span .
./span
```

Откройте [http://localhost:8080](http://localhost:8080) — владелец заводится при первом запуске из `-email` / `-password` (по умолчанию `you@example.com` / `span`).

### Docker

```bash
docker compose up -d
```

### Демо-данные

```bash
go run ./cmd/seed -db ./span.db
```

Три клиента, шесть проектов, две недели записей и уже идущий таймер.

## Как устроено

У **клиента** живут ставка, валюта и правило округления. **Проект** принадлежит клиенту и может переопределить ставку. **Запись** — отрезок времени на проекте, по умолчанию оплачиваемый.

Длительность считается при чтении, а не хранится: `ceil(минуты / шаг) * шаг`, где шаг берётся у клиента. Поменяли правило округления — пересчитался и прошлый месяц. Так и задумано: правило — часть договорённости, а не часть записи.

Отчёт группирует записи по клиентам и проектам, а `InvoiceLines` сворачивает оплачиваемые в одну строку на проект. Неоплачиваемое видно в отчёте и по построению отсутствует в позициях.

## Настройки

| Флаг | Переменная | По умолчанию | Смысл |
|---|---|---|---|
| `-addr` | `SPAN_ADDR` | `:8080` | адрес прослушивания |
| `-db` | `SPAN_DB` | `span.db` | файл SQLite |
| `-email` | `SPAN_EMAIL` | `you@example.com` | владелец, только при первом запуске |
| `-password` | `SPAN_PASSWORD` | `span` | пароль владельца, только при первом запуске |

Ключ подписи сессий генерируется при первом запуске и хранится в базе — после перезапуска входить заново не нужно.
